## 怎么编

需要 JDK 17、Android SDK(compileSdk 见 `app/build.gradle.kts`)、Gradle 8.9。
已经在 Windows 上真编过,`assembleDebug` 与 `testDebugUnitTest` 都过。

```bash
export JAVA_HOME=<你的 JDK 17>
export ANDROID_HOME=<你的 Android SDK>
cd android
"$GRADLE_HOME/bin/gradle" assembleDebug testDebugUnitTest
```

**这份文档里不写具体路径。** 这个项目在不止一台机器上开发,而写死的路径
在别的机器上不是"改一下就好" —— 它会让人以为那是要求,然后去建一个同名目录。
装在哪由 `JAVA_HOME` / `ANDROID_HOME` 回答,那两个变量本来就是干这个的。

`local.properties` 里要有 `sdk.dir=<你的 Android SDK>`,**它不进版本库**
(`.gitignore` 里有)—— 正是因为每台机器不一样。
用 Android Studio 打开 `android/` 目录会自己补上它。

产物在 `app/build/outputs/apk/debug/app-debug.apk`。

**单元测试只有纯逻辑那几个**(签名、白名单、验证码),不需要模拟器。
其中签名那一组是**跨端黄金向量**:同一组值服务端 `tests/test_api_auth.py`
也测一遍 —— 两边算得不一样的表现是所有请求 401 且服务端不说原因,
这是唯一能不联网就发现它的办法。

## 装好之后的三步

1. 服务端出一张配码:`python -m lifein.admin invite --user <uuid>`
2. 打开 App,**扫那个二维码**(`invite-<id>.html`),或者把那串粘进配置页。
   相机权限点了"扫码配置"才会要,不给也能用(粘贴那条路一直在)
3. 系统设置 → 通知使用权 → 允许 LifeIn 读取通知;
   再去电池优化里把它加进白名单(各家 ROM 位置不同)

### 两种配码,不要发错那一种

| 命令 | 二维码里是什么 | 能不能发给别人 |
| --- | --- | --- |
| `admin invite` | 一张**十分钟内、只能用一次**的换取码 | **能。** App 扫完自己去 `POST /enroll/claim` 换密钥 |
| `admin issue-device` | **明文的两把密钥** | **不能。** 发出去等于把密钥发在聊天里 |

App 两种都认,扫码和粘贴走同一条解析路径。默认用 `invite`:

- 换取码即使被截图拿到,也只有两种结局 —— 要么你已经换过了(他换不了),
  要么你还没换(你会发现自己换不了)。**两种都比"两个人各有一套"好**
- `issue-device` 留着,是因为自己给自己配码时它少一步:不需要服务端在线。
  但它打出来的那张图**不要经过任何聊天软件**

`device_id` 由 App 自己生成(`android-` + 12 位随机),第一次配码时存下来,
解绑重配拿回同一个。**不再由人现编一个名字**:人编的名字会重复(两个人都叫
`phone`),而重复的 `device_id` 意味着吊销一台会连带吊销另一台
([06 §6.15](../docs/06-data-model.md#615-一次性换取码配码-post-enrollclaim-p4))。

**换取中不要点第二次。** 一张码只能用一次;"超时了但服务端其实换成了"是完全
可能的,第二次点下去拿到 401,而那句"配码无效"会让人以为第一次也失败了。
所以按钮在换取期间是禁用的,文案会变成"正在换取密钥…"。

第 3 步做完之前,采集器一条也送不上去。做完之后服务端还要放行来源:
`python -m lifein.admin allow-source --user <uuid> --package com.tencent.mm`
—— 白名单默认拒绝([R10](../docs/05-risks.md#r10--手机端采集器的越权读取))。

4. 状态页里点"授予日历权限",否则日程会一直停在"未写入日历";
   **同一页往下勾要读哪几个日历** —— 默认一个都不读(06 §6.14),
   不勾的话日程不会进摘要,也不会被提取成待办
5. 长按桌面加小组件(可选)。它是**定时去拉**,受各家省电策略限制 ——
   是"看一眼"的入口,不是提醒机制(ADR-020)

## 装好之后怎么确认它真的在跑

按这个顺序看,每一步都能单独判断:

| 看哪 | 说明什么 |
| --- | --- |
| App 状态页"通知监听:已开启" | 手机这一侧的权限对了 |
| 状态页"待上报 N 条" | 采集器筛过之后**真的收到了东西**。一直是 0 说明白名单里那个 App 没发通知,或者被筛掉了 |
| 状态页"上次上报:收下 X 条" | 服务端收下了。X 是 0 而丢弃不是 0,多半是服务端白名单没放行 |
| `python -m lifein.admin list-sources --user <uuid>` | 服务端看到的心跳与白名单 |
| 服务端日志里的告警 | 超过一小时没心跳会发一封邮件(P1 验收标准) |

## base_url 必须是 https

配码里那个 `base_url` 写 `http://` 的话,安卓从 9 开始默认直接拒明文流量,
表现是所有请求都失败。**这正是要的**(架构 §8.3:传输走 HTTPS + 独立密钥),
所以没有开 `usesCleartextTraffic` 的口子 —— 内网自签证书也不行,
那等于把这条防线交给"反正是内网"这个假设。

## 已知的边界

- **通知监听只拿得到通知栏展示过的内容**:免打扰的群拿不到、长消息会截断、
  撤回和历史消息完全拿不到(ADR-010)
- **保活靠系统**:通知监听服务被 ROM 杀掉后系统会重绑,但自启动白名单要手动加。
  真掉线了靠服务端心跳告警发现,这是有意的选择(ADR-021)
- **小组件最快十五分钟一刷**,那是 WorkManager 的下限
- **`issue-device` 那张二维码里是明文的两把密钥**。自己从屏幕上扫、当场用掉
  没问题;发给别人不行。这一条 P4 已经解决(`admin invite` + `POST /enroll/claim`),
  但旧命令还在,所以坑也还在 —— 见上面"两种配码"那节
